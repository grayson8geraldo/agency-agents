## Агент 1: Tracking & Measurement Specialist — Диагностика трекинга

### Почему Facebook Pixel завышает данные

#### 1.1 Дублирование срабатываний пикселя
- Пиксель установлен дважды — через GTM и напрямую в код страницы
- SPA (Single Page Application) без корректной настройки — пиксель перезапускается на каждом виртуальном переходе
- GTM триггер настроен на `All Pages` вместо конкретного события
- **Проверка:** Event Manager → Data Sources → пиксель → вкладка "Events" → колонка "Deduplicated"

#### 1.2 Некорректная конфигурация события
- Событие `Lead` привязано к загрузке thank-you страницы, а не к реальной отправке формы
- Событие настроено на клик по кнопке "Отправить", а не на успешный callback от сервера
- Auto-tracking плагины (Elementor, Contact Form 7) могут автоматически стрелять `fbq('track', 'Lead')` при любом взаимодействии с формой

#### 1.3 View-Through Attribution раздувает числа
- Настройка "1-day view": пользователь увидел рекламу (без клика), затем самостоятельно перешёл на сайт → Facebook засчитывает конверсию себе
- При охвате 1,185 человек и 36 "лидах" — конверсия 3.04% от охвата, нереально для холодной аудитории

#### 1.4 CAPI без дедупликации
- Если настроен Conversions API параллельно с браузерным пикселем без `event_id` — каждая конверсия считается дважды

### Почему собственный чекер может занижать

- Блокировщики рекламы (25-40% пользователей) скрывают клиентский JS трекинг
- Safari ITP ограничивает cookies первых лиц 7 днями
- Редиректы теряют UTM-параметры и fbclid
- Медленная загрузка: 12 кликов не конвертировались в просмотр страницы

### Пошаговая техническая диагностика

**Шаг 1: Facebook Pixel Helper (Chrome)**
```
1. Открыть лендинг в режиме инкогнито
2. Проверить сколько раз загружается Base Code пикселя (должен быть 1)
3. Проверить какие события стреляют при открытии страницы (Lead НЕ должен)
4. Заполнить форму → Lead должен сработать ОДИН раз
5. Обновить страницу → Lead НЕ должен срабатывать повторно
```

**Шаг 2: Events Manager**
```
Meta Business Suite → Events Manager → Data Sources → Пиксель
- Вкладка "Overview": предупреждения о дублировании?
- Вкладка "Events" → Lead: Received vs Deduplicated
- "Event Match Quality": оценка ниже 6 = проблемы с матчингом
```

**Шаг 3: Test Events Tool**
```
Events Manager → Test Events
1. Скопировать Test Event Code
2. Открыть лендинг → пройти весь путь конверсии
3. В реальном времени смотреть: есть ли дубли? Какой payload?
```

**Шаг 4: Изменить Attribution Window**
```
Ads Manager → Ad Set → Edit → Attribution Setting
Изменить на: 7-day click only (убрать view и engaged-view)
Сравнить количество конверсий
```

### Исправление триггера события Lead

**Неправильно (вероятная текущая ситуация):**
```javascript
// Стреляет при клике — ДО ответа сервера
document.getElementById('submit-btn').addEventListener('click', function() {
    fbq('track', 'Lead');
});
```

**Правильно:**
```javascript
// Стреляет только после успешного ответа сервера
fetch('/submit-form', {
    method: 'POST',
    body: formData
}).then(response => {
    if (response.ok) {
        fbq('track', 'Lead', {}, {eventID: generateUniqueEventID()});
    }
});
```

### Дедупликация CAPI + Pixel
```javascript
const eventID = 'lead_' + Date.now() + '_' + Math.random().toString(36).substr(2, 9);

// В браузерном пикселе
fbq('track', 'Lead', { content_name: 'New Leads Ad Form' }, { eventID: eventID });

// На сервере — передать тот же eventID в CAPI
sendToServer({ eventID: eventID, eventType: 'Lead' });
```

### Диагностическая матрица

| Вероятная причина | Вероятность | Влияние | Сложность исправления |
|---|---|---|---|
| View-through attribution | Высокая | +10-15 ложных конверсий | Низкая (настройка в Ads Manager) |
| Дублирование пикселя | Средняя | +5-10 конверсий | Средняя (аудит кода) |
| Триггер на клик, а не на успех | Высокая | +5-8 конверсий | Средняя (правка кода) |
| CAPI без дедупликации | Средняя | x2 дубли | Средняя (добавить event_id) |
| Блокировщики (потери в CRM) | Средняя | -1-2 в CRM | Высокая (серверный трекинг) |

## Агент 3: Paid Media Auditor — Форензик-аудит

### Аномалия: All Clicks (83) < Link Clicks (85)

Это математически невозможно: All Clicks всегда >= Link Clicks. Причины:

1. **Race Condition** — метрики обрабатываются разными серверами с задержкой
2. **Разный уровень дедупликации IVT** — Facebook мог идентифицировать часть кликов как подозрительные и исключить из All Clicks, но не из Link Clicks. Косвенное признание недействительного трафика
3. **Баг в API отчётности** — данные из разных Attribution Windows несимметрично

### Декомпозиция 36 "лидов" по атрибуции

```
36 всего (предполагаемая структура):
├── 7-day click attribution:     ~15-20 лидов
├── 1-day view attribution:      ~8-12 лидов (фантомные)
├── 1-day engaged-view:          ~4-8 лидов
└── Реальные немедленные лиды:   3 лида
```

**1-Day View — наиболее злоупотребляемый тип:**
- Охват 1,185 → при конверсии сайта 0.5-2% = 6-24 органических конверсии могут быть атрибутированы Facebook
- Facebook не различает: конверсия "благодаря" рекламе или "несмотря на неё"

## Заключение

Кампания демонстрирует **критическую ошибку трекинга** с коэффициентом расхождения 12:1. Наиболее вероятные причины:

1. **Мисконфигурация пикселя** (85% вероятность) — событие Lead срабатывает при загрузке страницы или клике, а не при реальной отправке формы
2. **View-through attribution** (80% вероятность) — широкое окно атрибуции присваивает органические конверсии рекламе
3. **Потенциальный Invalid Traffic** (55% вероятность) — аномальный CTR и расхождение All/Link Clicks

**Первое действие прямо сейчас:** Прямо сейчас изменить Attribution Setting на `1-day click only` и сравнить показатели. Если число упадёт с 36 до 3-7 — гипотеза подтверждена.

**Реальный CPL $20.16** может быть жизнеспособным в зависимости от вашей ниши, но принимать любые решения о масштабировании до исправления трекинга — значит строить на ложном фундаменте.
